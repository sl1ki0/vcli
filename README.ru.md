# vcli

[English](README.md) · [Русский](README.ru.md) · [简体中文](README.zh-CN.md)

Основная документация ведётся на английском. Файлы README на русском и упрощённом
китайском — это переводы данного руководства; названия команд, ключи конфигурации
и подписи в интерфейсе остаются без изменений. Подробные руководства в `docs/`
пока доступны на английском.

Агент для разработки с приоритетом архитектуры. Изучайте граф исходного кода,
задавайте границы компонентов и наблюдайте, как архитектурный замысел превращается в код прямо
в терминальном рабочем пространстве.

TypeScript · Bun · OpenTUI/Solid · SQLite · ELK · resvg

## Что можно делать

- Изучать обнаруженные в исходном коде зависимости, задавать целевую архитектуру
  компонентов и просматривать изменения с момента открытия рабочего пространства.
  Проверять объявленные границы локально.
- Общаться в потоковом Markdown-чате, переключаться между разделённым и полноэкранным
  режимами, возобновлять сохранённые разговоры и просматривать сохраняемые карточки
  вызовов инструментов и полные результаты.
- Составлять план без изменения исходников, а затем явно включать реализацию.
  Использовать постоянные задачи, память проекта, защищённые контрольные точки файлов,
  хуки инструментов и доступных только для чтения исследователей.
- Подключать один из пяти адаптеров провайдеров и явно выбирать модель, уровень
  рассуждений, режим разрешений и лимиты токенов.
- Обнаруживать навыки и инструменты MCP по запросу, в том числе поддерживаемые
  компоненты из распознаваемых форматов плагинов и каталогов.

Анализ зависимостей исходного кода сосредоточен на TypeScript и JavaScript и использует
Compiler API. Другие распознаваемые исходные файлы отображаются как узлы файлов;
углублённый анализ дополнительных языков пока не реализован. Сканирование архитектуры,
раскладка, навигация и экспорт выполняются локально без вызовов модели. Диалоги для
написания кода и модели-исследователи используют выбранный API.

## Начало работы

Для загруженной сборки выполните `./vcli --root /path/to/your/project`. Если проект
или провайдер ещё не настроен, откроется приветственный экран. Выберите **Open project**
и **Connect provider**. Нажмите **F1**, чтобы открыть меню команд, или **Esc**, чтобы
вернуться к строке ввода и набрать `/help`, `/open` или `/connect`. В каждую сборку
входит [краткое руководство](docs/artifact-quickstart.md).

Загруженные сборки работают самостоятельно; Bun нужен для разработки из исходного
кода. Чтобы запустить проект из исходников, установите **Bun 1.3.13** и **ripgrep**,
затем выполните:

```sh
git clone https://github.com/sl1ki0/vcli.git
cd vcli
git switch codex/architecture-first-cli
bun install --frozen-lockfile
bun run dev --root fixtures/sample-project
```

Если терминал поддерживает Kitty или Sixel, холст отображает графику по этим протоколам.
В неподдерживаемых терминалах отображается дерево, по которому можно перемещаться.
Сканирование, навигация и экспорт не расходуют токены модели.

Выберите провайдера и модель через `/connect` или запустите настройку напрямую:

```sh
bun run dev setup --root fixtures/sample-project
```

Во время настройки API-ключ вводится в скрытом поле. Можно оставить его только для
текущего запуска или сохранить в незашифрованном файле учётных данных, доступном
только пользователю. Настройки сохраняются для выбранного проекта. Ключи хранятся
отдельно от конфигурации проекта и никогда не отображаются в статусе или выводе
конфигурации. Можно также использовать переменные окружения и обычную настройку
оболочки:

```sh
bun run dev config set provider openai
bun run dev config set model YOUR_MODEL_ID
export OPENAI_API_KEY="YOUR_KEY"
bun run dev
```

| Провайдер                          | Настройка    | Учётные данные                        |
| ---------------------------------- | ------------ | ------------------------------------- |
| OpenAI Responses                   | `openai`     | `OPENAI_API_KEY`                      |
| Anthropic Messages                 | `anthropic`  | `ANTHROPIC_API_KEY`                   |
| Gemini                             | `gemini`     | `GEMINI_API_KEY` или `GOOGLE_API_KEY` |
| OpenRouter Chat Completions        | `openrouter` | `OPENROUTER_API_KEY`                  |
| OpenAI-compatible Chat Completions | `compatible` | `VCLI_COMPATIBLE_API_KEY`, если нужен |

Для совместимого сервера также задайте `baseURL`, указав базовый URL его API.
Идентификаторы моделей нужно выбирать явно: vcli не предполагает входа через подписку
и не выбирает за пользователя платную модель по умолчанию. Консервативный размер
контекстного окна по умолчанию — 32,768 токенов. Укажите документированный лимит
своей модели в `contextWindow`; перед подготовкой контекста из него вычитается резерв
для ответа.

По умолчанию OpenRouter использует `https://openrouter.ai/api/v1`. Явно выберите
идентификатор модели шлюза, например `provider/model` из вашей учётной записи, через
`/connect`. Учётные данные привязаны к выбранному провайдеру и конечной точке.

**По умолчанию включён YOLO:** агент использует доступные права файловой системы
и сети без запросов на подтверждение. Установите `permission` в `ask` или `read-only`
либо передайте `--permission` для одного запуска. В режиме ask выполнение запрещено,
если недоступен интерактивный канал подтверждения. Режим разрешений не является
песочницей файловой системы.

В рабочем пространстве запросы разрешений показывают выделенное меню: **Allow once**,
**Always allow this tool for this conversation** или **Deny**. Для выбора используйте
**Up/Down**, для подтверждения — **Enter**; **Esc** означает отказ. Каждый запрос
изначально выделяет **Deny**. Подробности можно прокручивать клавишами **Page Up/Down**.
Запомненные разрешения для инструментов сохраняются после перезапуска этого разговора;
в новых разговорах подтверждение запрашивается заново. При изменении контракта
инструмента требуется новое подтверждение. Режимы plan и read-only по-прежнему
запрещают изменения.

## Чат и архитектурное рабочее пространство

При открытии рабочего пространства одновременно видны архитектура и чат. Выберите
**Chat**, нажмите **F2** или введите `/chat`, чтобы скрыть архитектуру и отвести всё
рабочее пространство под разговор. `/split` возвращает оба представления; **F3** или
`/architecture` разворачивает холст. В широком архитектурном представлении есть дерево
модулей и инспектор исходного кода; в узких терминалах можно переключаться между
холстом, деревом и инспектором.

Отправленное сообщение появляется сразу. Ответы выводятся под ним по мере поступления;
видны ожидание, размышления, действия инструментов и отмена. Markdown отображает
заголовки, выделение, встроенный код, списки, ссылки, таблицы и блоки кода. Нажмите
на сообщение или клавишу **Tab**, чтобы перейти к чату; для прокрутки используйте
колесо мыши или **Page Up/Down**. **Up/Down** перемещают между сообщениями, а **Home/End**
переносят к первому или последнему сообщению. Нажмите **Esc**, чтобы вернуться к строке
ввода. Нажатие **Up** в пустой строке ввода восстанавливает отправленное сообщение.

Введите `/history` (или `/sessions`), чтобы выбрать сохранённый разговор. `/new`
создаёт отдельную задачу. История хранится локально, включая частичные ответы,
оставшиеся после прерывания, независимо от лимита контекста модели. Просмотр и смена
разговоров в истории не вызывают модель.

Вызовы инструментов отображаются в разговоре карточками с действием, целью и статусом:
waiting, running, succeeded, failed, interrupted или blocked. Ошибки остаются
видимыми; выберите карточку и нажмите **Space/Enter** (или щёлкните по её заголовку),
чтобы увидеть подписанные аргументы и предварительный результат. Нажмите **F**, чтобы
локально открыть полный сохранённый результат; клавиши **Left/Right** перемещают по его
страницам. Карточки и ссылки на результаты переживают перезапуск; старые сохранённые
сессии восстанавливают историю инструментов из локального журнала событий.

Три повторные ошибки проверки аргументов одного инструмента с одной и той же проблемой
схемы останавливают
текущую задачу до следующего запроса к модели. Исправление аргументов сбрасывает счётчик
этого инструмента. Остановка сохраняется после перезапуска; чтобы продолжить, отправьте
новое сообщение. Отказы в разрешении и ошибки выполнения инструмента в этот лимит
не входят.

| Клавиша                  | Действие                                          |
| ------------------------ | ------------------------------------------------- |
| Tab                      | Переключать фокус между вводом, холстом и чатом   |
| Стрелки / щелчок мышью   | Выбрать модуль                                    |
| Shift + стрелки          | Переместить холст                                 |
| `+` / `-`                | Изменить масштаб                                  |
| Enter                    | Открыть модуль или группу                         |
| Space                    | Свернуть родительский элемент                     |
| `v`                      | Observed → intended → changes                     |
| `/`                      | Искать модули                                     |
| `t`                      | Показать/скрыть дерево; переключать узкие панели  |
| Escape                   | Сбросить поиск, переход и область просмотра       |
| `r`                      | Обновить данные из исходного кода                 |
| Ctrl+C                   | Остановить задачу; выйти, если задача не запущена |
| `q` при фокусе на холсте | Выйти                                             |
| F1                       | Открыть меню команд                               |
| F2                       | Переключить полный чат и разделённый вид          |
| F3                       | Переключить полную архитектуру и разделённый вид  |

| Команды в строке ввода                        | Назначение                                          |
| --------------------------------------------- | --------------------------------------------------- |
| `/help`, `/commands`                          | Открыть меню команд                                 |
| `/open`, `/connect`, `/config`, `/status`     | Проект, провайдер и настройки                       |
| `/tokens`, `/reasoning`, `/permission`        | Лимиты, усилие модели и разрешения                  |
| `/chat`, `/split`, `/architecture`            | Компоновка рабочего пространства                    |
| `/history`, `/sessions`, `/new`               | Сохранённые и новые разговоры                       |
| `/observed`, `/intended`, `/changes`, `/scan` | Представления архитектуры и обновление              |
| `/plan`, `/build`, `/plans`                   | Планирование, реализация и сохранённые планы        |
| `/memory`, `/tasks`, `/hooks`                 | Просмотр состояния локальных процессов              |
| `/checkpoints`, `/rewind <id>`                | Просмотр и восстановление сохранённых правок файлов |
| `/plugins`, `/skills`                         | Просмотр доступных расширений                       |

Введите `/` в строке ввода, чтобы увидеть команды с описаниями; продолжайте вводить,
чтобы отфильтровать список. Используйте **↑/↓** для выбора, **Tab** для автодополнения
и **Esc**, чтобы скрыть подсказки, сохранив черновик. **Enter** дополняет неполную
команду; нажмите ещё раз, чтобы выполнить её. Полностью введённые команды запускаются
по **Enter**. Для `/permission` и `/reasoning` также предлагаются поддерживаемые
аргументы. Нажмите на подсказку, чтобы вставить её в строку ввода. Если подсказки
закрыты, **Tab** переключает фокус. Подсказки не вызывают модель. Настройка и навигация
тоже не вызывают модель. Команда `/tokens` изменяет размер контекстного окна, лимиты
prompt/result/schema/map, резерв для ответа и бюджет задачи.

Команда `/reasoning` выбирает `default`, `none`, `minimal`, `low`, `medium`, `high`,
`xhigh` или `max`. Значение `default` сохраняет собственное поведение модели; доступные
уровни зависят от провайдера и модели. Известные несовместимые варианты отклоняются до
сохранения. Рассуждения, переданные провайдером, отображаются в сворачиваемом разделе
ответа; непрозрачные данные продолжения хранятся отдельно от видимого текста.
Выберите сообщение ассистента и нажмите **Space** или **Enter**, чтобы показать или
скрыть полученные рассуждения, либо нажмите на раздел рассуждений.

Целевая архитектура показывается сразу после завершения `architecture_propose` и до
начала следующего изменения. После правок исходников выполняется сверка; обновление
в состоянии покоя также обнаруживает внешние изменения. Изменения сравниваются с графом,
сохранённым при открытии рабочего пространства.

```sh
vcli architecture scan --root ./project --json
vcli architecture view --root ./project --renderer kitty
vcli architecture export --root ./project --format png --output architecture.png
vcli architecture export --root ./project --format svg
vcli architecture export --root ./project --format json
vcli architecture check --root ./project
```

Параметры рендерера: `auto`, `kitty`, `sixel`, `blocks`, `off`. В режиме auto внутри
терминальных мультиплексоров выбирается дерево, если явно не запрошена графика. О том,
что проверено и какие проверки в реальных терминалах ещё нужны, читайте в
[отчёте о проверке терминалов](docs/validation.md).

Целевые компоненты и правила зависимостей хранятся в `.vcli/architecture.json`.
Добавьте этот файл в коммиты. Производные индексы, сессии SQLite и полные результаты
инструментов хранятся в `.vcli/state/` и `.vcli/artifacts/`; добавьте оба пути
в `.gitignore` проекта. Примеры формата версии 1 находятся в
[примерном проекте](fixtures/sample-project/.vcli/architecture.json) и в
[описании собственной архитектуры vcli](.vcli/architecture.json). Если `dependencies`
не указано, разрешены любые зависимости между компонентами; явный массив задаёт список
разрешённых зависимостей. `forbiddenDependencies` имеет приоритет. При нарушениях
проверка дрейфа приводит доказательства из исходного кода и завершается с кодом 1.

## Задачи, сессии и бюджеты токенов

```sh
vcli run "Extract persistence into a storage component and verify the tests"
vcli run "Inspect the module boundaries" --permission read-only --json
vcli run "Plan the API boundary change" --plan --json
vcli sessions list
vcli sessions resume SESSION_ID "Continue and verify the result"
vcli sessions resume PLAN_SESSION_ID "Implement the plan" --build
```

Параметр `--json` выводит события среды выполнения построчно, без управляющих
последовательностей терминала. Результаты прерванных изменений остаются в журнале;
при возобновлении они проверяются. vcli никогда не повторяет их автоматически. При
смене провайдера данные продолжения, специфичные для прежнего провайдера, удаляются;
переносимые сообщения и состояние задачи сохраняются.

Сбалансированные значения по умолчанию можно настроить:

| Параметр               |         Значение по умолчанию |
| ---------------------- | ----------------------------: |
| `context.promptTokens` |          целевой лимит 32,000 |
| `context.mapTokens`    |                         4,000 |
| `context.schemaTokens` |                         4,000 |
| `context.resultTokens` |                         3,000 |
| `context.outputTokens` |                  резерв 8,000 |
| `context.maxTurns`     |                            40 |
| `context.taskTokens`   | Не задано; общий лимит задачи |

```sh
vcli config set context.taskTokens 100000
vcli config set permission ask --project
vcli config set reasoning high --project
vcli config show
```

Приоритет настроек: параметры CLI → `.vcli/config.json` проекта → пользовательский
`~/.config/vcli/config.json` → значения по умолчанию. Переменная `VCLI_CONFIG_HOME`
меняет расположение пользовательского каталога. Учётные данные берутся из переменных
окружения, текущего запуска или отдельного пользовательского хранилища. Размер
контекста оценивается как число байтов UTF-8, делённое на три; сообщаемые провайдером
значения входных, выходных и кешированных токенов записываются отдельно. Повторно
используемые пересекающиеся результаты чтения опускаются, полные результаты остаются
доступными, а старые завершённые группы инструментов удаляются из контекста, сохраняя
долговременный журнал. В этой версии нет платного этапа суммаризации. Схемы неизвестных
расширений и содержимое навыков загружаются только после обнаружения.

Перед каждым вызовом модели бюджеты задач резервируют оценку входных данных и лимит
ответа. Полученные сведения об использовании корректируют резерв; если сведения
отсутствуют или запрос прерван, резерв сохраняется при возобновлении, поэтому отсутствие
отчёта об использовании не позволяет обойти лимит.

[Воспроизводимый офлайн-бенчмарк](docs/benchmarks.md) сравнивает одинаковые задачи
с полным исходным кодом и полными схемами в запросе. Он измеряет подготовленный контекст
и локальную задержку; доля успешных ответов живых моделей и экономия на оплате услуг
провайдеров не установлены.

## Навыки, MCP и каталоги плагинов

Навыки проекта обнаруживаются в `.vcli/skills`, `.agents/skills`, `.claude/skills`,
`.gemini/skills` и `.qwen/skills`. Распознаваемые Agent Plugins, пакеты и каталоги
Claude и Codex, расширения Gemini и Qwen, а также пакеты Qoder преобразуются
в поддерживаемые навыки и серверы MCP. Хуки, команды, агенты и элементы интерфейса
исходных платформ, не поддерживаемые vcli, отмечаются как неподдерживаемые. Для учётных
данных и подключённых аккаунтов приложений нужны отдельные интеграции.

```sh
vcli plugins formats
vcli plugins inspect ./my-plugin
vcli plugins install ./my-plugin
vcli plugins install ./multi-host-plugin --format qwen
vcli plugins install https://github.com/team/plugins.git --ref COMMIT_SHA --subdir plugins/design
vcli plugins list
vcli plugins marketplace add team https://github.com/team/catalog.git --ref COMMIT_SHA
vcli plugins marketplace list
vcli plugins install design --marketplace team
vcli plugins marketplace refresh team
vcli plugins remove design
```

Установка копирует снимок и записывает его происхождение. Хуки не запускаются при
установке. Источником может быть локальный каталог или Git-репозиторий. Установка
из архивов или npm, отдельные HTTP-каталоги, legacy SSE и интерактивный OAuth не
поддерживаются. Программы MCP через stdio и HTTP-подключения запускаются при обнаружении
через шлюз разрешений. Схемы загружаются по запросу, аргументы проверяются, отменённые
и неопределённые вызовы не повторяются. Поддерживаются транспорты stdio и Streamable
HTTP. Ограничения конфигурации, совместимости импорта и хранения описаны в документах
[об интеграциях](packages/integrations/README.md) и
[о совместимости расширений](docs/extension-compatibility.md).

## Локальные процессы разработки

Используйте `/plan`, чтобы изучить задачу и просмотреть проект архитектуры без изменения
исходников, затем `/build`, чтобы перейти к реализации. Команды `/plans`, `/memory`,
`/tasks`, `/hooks` и `/checkpoints` просматривают локальные записи без вызова модели.
`/rewind <id>` восстанавливает сохранённую правку файла, только если файл всё ещё
соответствует этой правке.

Среда загружает корневые инструкции проекта и поддерживает постоянную память с проверкой
версии, задачи с учётом зависимостей, хуки-команды до и после инструмента, а также до
двух изолированных моделей-исследователей, доступных только для чтения и использующих
общий бюджет токенов родительской задачи. Встроенные инструменты для работы со списком
файлов и Git diff доступны через отложенное обнаружение.

Подробности о командах, настройке хуков, подсчёте токенов, охвате контрольных точек
и матрице поддержки приведены в документации о [локальных процессах разработки](docs/local-workflows.md).
Эти функции реализованы независимо на основе документированных процессов; полной
совместимости с Claude Code не заявляется.

Режим plan сохраняется при возобновлении и запрещает редактирование исходников,
выполнение команд, хуки и запуск MCP даже при YOLO. Команда `/build` разрешает
реализацию в рамках настроенного режима разрешений. Восстановление активного
предварительного просмотра после перезапуска пока не реализовано. Автоматически
загружаются корневые `AGENTS.md`, `CLAUDE.md` и `.vcli/MEMORY.md`; общий лимит для них —
2,000 токенов. Вложенные инструкции и импорты не интерпретируются. Исследователи могут
только читать данные; одновременно запускается не более двух, каждый работает не более
шести ходов и по умолчанию получает из бюджета родительской задачи лимит 12,000 токенов.
Контрольные точки охватывают встроенные операции изменения файлов, но не действия shell, MCP, памяти
и архитектурного дизайна; историю чата они не перематывают.

## Структура репозитория

| Путь                           | Ответственность                                                             |
| ------------------------------ | --------------------------------------------------------------------------- |
| `packages/core`                | Переносимые контракты, среда агента, контекст, бюджеты и разрешения         |
| `packages/architecture`        | Анализ исходников, целевая архитектура, дрейф, раскладка, экспорт SVG/PNG   |
| `packages/providers`           | Адаптеры SDK провайдеров, нормализованные потоки и состояние продолжения    |
| `packages/integrations`        | Нормализация плагинов/каталогов, навыки и MCP-клиенты с отложенным запуском |
| `packages/tui`                 | Представление рабочего пространства, чат и контроллеры навигации            |
| `apps/cli`                     | Команды, конфигурация, инструменты, локальные процессы и драйверы SQLite    |
| `scripts`, `tests`, `fixtures` | Сборка, smoke-проверка, бенчмарки и офлайн-проверка                         |

В core нет импортов терминальных библиотек, SDK провайдеров, файловой системы,
подпроцессов и специфичных для Bun API. Движок архитектуры не запускает инференс;
TUI не владеет инструментами агента. Границы пакетов задаются и проверяются
в `.vcli/architecture.json`.

## Разработка и упаковка

```sh
bun run format:check
bun run check
bun test
bun run dev architecture check
bun run benchmark
bun run build
bun run smoke
./dist/vcli --help
```

Сборка создаёт `dist/vcli` для текущей платформы, включая worker раскладки и шрифт
для графики. Распространяйте весь каталог `dist/`, включая лицензии, уведомления,
руководство для загруженной сборки и `WORKFLOWS.md`. CI запускается на macOS и Linux,
включая нативные сборки и проверки исходной и скомпилированной версии в псевдотерминале
за пределами репозитория. Smoke-набор также проверяет восстановление терминала,
вывод изображений и лимит в 256 открытых файловых дескрипторов.

Для тестов используются офлайн-фикстуры и локальные серверы провайдеров; они не
устанавливают долю успешных ответов живых моделей или экономию платных токенов.
Ручная проверка в настоящих терминальных приложениях и WSL ещё не завершена.
Нативная Windows, браузерные/IDE-сервисы, вход через подписку, фоновые агенты,
агенты с правом записи, пользовательские агенты и углублённый анализ дополнительных
языков пока не реализованы.

В [руководстве по архитектуре](docs/architecture.md) описаны контракты и границы
пакетов. В [исследовательских заметках](docs/research.md) собраны публичные источники
и рамки независимой реализации. Форматирование выполняется автоматически, команды
и инструменты разнесены по профильным модулям, а core не импортирует терминальные
библиотеки, SDK провайдеров или API Bun.
